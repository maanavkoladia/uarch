# Fanout-violation analyzer & guided fixer

This folder hosts the Design Vision fanout check and the helper script we use to drive its remediation. It is meant to be picked up cold by a future session — the goal, the workflow, and where everything lives are all written down here.

## Goal

The memory subsystem (`Everywhere_TOP`) is being closed at an **8 ns** target. The synthesis fanout rule (`fanout.tcl:426-437`) requires that any net with fanout > 4 be driven by a `bufferH<N>$` / `bufferHInv<N>$` whose drive class matches the load count (tier-16 / 64 / 256 / 1024 / 4096). Every violation is fixed using one of three structural moves, ranked by added delay:

| Strategy | Best when… | Added delay |
|---|---|---|
| **Register duplication** | driver is sequential (`reg64e$`, `dff*$`, `MPS_reg_rst_we$`) | **0 ns** — clones run in parallel; same Tcq |
| **Fanin-tree replication** | driver is small comb logic fed from a register (FSM SOP terms, narrow NAND/AND) | **0 ns** — duplicate register *and* its fanin gates |
| **Buffer insertion** | driver is wide comb (mux/bus/comparator) or a high-fanout broadcast | one buffer-tier delay |

Timing is the binding constraint — area/power are not. The user has explicitly authorized:
- "do not worry about hardware at all… do not limit yourself by adding registers"
- "use the buffers from lib2 do not use the macro buffers" (instantiate `bufferH16$` / `bufferH256$` etc. directly, not `INV_N`/`BUFFER_DELAY` macros)
- "adding buffers isn't just free if it creates more fanout" — the cascade of an *input* buffer feeding the new output buffer is part of the cost. The script's `best_dup_strategy` accounts for that.
- "ignore any clk related things" — `clk` / `rst` are tagged INFO and are CTS-handled; out of scope.

## Workflow (one round)

1. **Regenerate check.log.** The user runs `make check` from this folder (Synopsys env required — the assistant cannot run it). After the run, `check.log` is the current state.

2. **Run the analyzer.**
   ```
   python3 scripts/fanout_optimize.py \
       --check-log ./check.log \
       --module <icache|dcache|mem|busArb|dma|ddr5|all> \
       --output reports/<module>_fanout_plan.md
   ```
   No external deps; Python ≥3.6.

3. **Read the report.** Each violation is listed with:
   - driver cell, hierarchy path, fanout, required tier
   - **Option A** (register duplication / fanin replication) with computed `K`, per-copy load count, total cascade delay
   - **Option B** (buffer insertion) with tier and delay
   - the recommendation (lower-delay option first)

   A trailing **cross-module appendix** lists violations whose driver is in *another* module but whose loads concentrate inside the requested module — fix at the boundary or in the upstream file.

4. **Apply fixes** in the corresponding `rtl/<module>/structural/fanout/` files. Edit only the fanout-folder copies — never the originals (auto-generated FSM files in `gen/` carry a "do not hand-edit" warning anyway).

5. **Backup `check.log`** before re-running: `cp check.log check.log.<module>_r<N>` so progress is traceable round-to-round.

6. **Repeat** until the analyzer reports 0 in-scope violations for that module. Then move to the next module.

## Cost model (encoded in `fanout_optimize.py`)

Buffer delays from `lib/Gates/lib2.v` (typical mid `t_p` in ns):

| Cell | Drive | Delay | Polarity |
|---|---|---|---|
| `bufferH16$`     | ≤16   | 0.24 | non-inv |
| `bufferH64$`     | ≤64   | 0.30 | non-inv |
| `bufferH256$`    | ≤256  | 0.54 | non-inv |
| `bufferH1024$`   | ≤1024 | 0.60 | non-inv |
| `bufferH4096$`   | ≤4096 | 0.80 | non-inv |
| `bufferHInv16$`  | ≤16   | 0.15 | inverting |
| `bufferHInv64$`  | ≤64   | 0.39 | inverting |
| `bufferHInv256$` | ≤256  | 0.45 | inverting |
| `bufferHInv1024$`| ≤1024 | 0.69 | inverting |
| `bufferHInv4096$`| ≤4096 | 0.89 | inverting |

`bufferHInv*$` is only the cheaper choice at the **tier-16** band, and only when downstream logic can absorb the inversion (NAND→AND swap, mux-select polarity flip). At tier-64+, non-inverting is already faster than a single inverting buffer, and a polarity-restoring inverter pair is always more expensive.

## Common gotchas (the script flags these)

1. **`inv_N$` macro** maps to `bufferHInv64$` in `lib/STDCells/UniqueLib.v`. Good for ≤64 inverting fanouts; for >64 use `bufferHInv256$` directly from `lib2`.
2. **Generated FSM files** (`*/gen/*.sv`) are untouchable. Always edit the copy in the module's `fanout/` folder; `master.txt` decides which version Design Vision sees.
3. **`addressBus` non-tristate violations** — driver is the wrong class for a tristate bus; fix is `BUS_TRISTATE` in place of `TRISTATE_L`, not a buffer.
4. **Tied-constant / tristate-bus INFOs** are filtered out by the script (already classified by `fanout.tcl`).
5. **`clk`, `rst`** show very high fanout but are tagged INFO — out of scope (CTS handles them).
6. **Cross-module fanout** (e.g. `DTE_MEM_2_ICache_FSM.mem_valid_o` driving ICache loads) is reported under both modules. Fix either by (a) re-buffering at the load module's input port, or (b) editing the driver module — usually (a) is cleaner.
7. **Cascade cost is real**: when you insert an output buffer, its `in` becomes a new high-fanout net if the original driver was already wide. The analyzer's `best_dup_strategy` searches `K` (number of register copies) to minimize `D_input_buffer_delay + per_copy_output_buffer_delay`.

## Quick commands

```bash
# Regenerate the report for the current focus module
python3 scripts/fanout_optimize.py --check-log ./check.log --module mem \
        --output reports/mem_fanout_plan_R<N>.md

# Snapshot the log before each round
cp check.log check.log.mem_r<N>

# Run the synthesis fanout check (user only — needs synopsys env)
make check

# Swap a module's RTL source in master.txt to point at fanout/ overrides
#   then re-run `make check`
```

## What the script *cannot* do

- Prove that a polarity flip is functionally safe (it flags the optimization, doesn't apply it).
- Use STA / critical-path data — recommendations are based on the static buffer cost model only. If a path turns out to be slack-rich, a slightly cheaper option (single inverter + downstream polarity flip) might be safe to skip.
- Auto-create per-module `fanout/` folders. Each one needs a one-time seed (copy of the relevant structural files into the new folder, plus the `master.txt` swap).
- Run `make check` itself — license + PATH belong to the user.
